## Bug 修复：管理后台点"通过"审核提示"作品不存在"

**根因**：项目升级到 **Next.js 16.1.2** 后，App Router 的 route handler 里 `params` 变成了 **Promise**，但 `frontend/app/api/admin/camp/works/[id]/route.ts` 的 GET/PATCH/DELETE 还按老写法直接解构 `const { id } = params;`，导致 `id` 实际是 `undefined`（或 Promise 对象），`db.campWork.findUnique({ where: { id } })` 查不到记录，于是返回 404"作品不存在"。

**影响面**：不只 camp/works，所有带 `[id]` 的动态路由 handler 都有同样隐患。我一次性修了 6 个文件共 11 个 handler：
1. `frontend/app/api/admin/camp/works/[id]/route.ts` — GET/PATCH/DELETE
2. `frontend/app/api/admin/camp/students/[id]/route.ts` — GET/PATCH/DELETE
3. `frontend/app/api/admin/camp/logs/[id]/route.ts` — GET/PATCH/DELETE
4. `frontend/app/api/camp/works/[id]/route.ts` — GET（本次新增）
5. `frontend/app/api/integrations/jobs/[id]/route.ts` — GET
6. `frontend/app/api/integrations/jobs/[id]/retry/route.ts` — POST

**改法**：把 handler 签名里的 `params: { id: string }` 改成 `params: Promise<{ id: string }>`，并在函数体第一行 `const { id } = await params;`，后面全部改用 `id` 而不是 `params.id`。

**验证**：TypeScript 层面没有 `params: { id:` 残留；由于沙箱 safe-delete 问题未跑完整 `next dev`。需要用户重新部署 frontend 后到线上点"通过"验证。

**教训**：Next.js 15+ App Router 的动态路由 `params` 是异步 Promise，不只是 page.tsx，route.ts 的 handler 也必须 await。以后新增或审查 `[id]` 路由时，第一件事就是检查 `await params`。
