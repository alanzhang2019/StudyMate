## 9:00–9:30 🔴 紧急代码规范 30 min（必看）

> **不铲除这三个坑，CSP-S 选+判就算做对，完善程序也会 TLE/WA**。

### 9:00–9:10 `#define int long long` 替换

**改成**：
```cpp
using ll = long long;       // ✅ 显式
// 仅在可能溢出的变量上用 ll
int a, b; ll sum;            // a, b 是 int，sum 是 ll
// 而不是：
#define int long long        // ❌ 全员 long long，内存 ×2，时间 ×2
```

**当场验证**：[P1002 过河卒](https://www.luogu.com.cn/problem/P1002) 用 `ll` 重写一遍，要求 5 min 内 AC。

### 9:10–9:20 `ios::sync_with_stdio` 必加

**所有 `cin/cout` 代码开头必加**：
```cpp
int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    // ...
}
```

**当场验证**：[P1049 装箱问题](https://www.luogu.com.cn/problem/P1049) 用新规范重写一遍，要求 7 min 内 AC。

### 9:20–9:30 边界检查 / 暴力陷阱

- 数组下标：0 还是 1？循环到 `n-1` 还是 `n`？
- 边界值：`n=0`、`n=1`、`n=max` 单独手算一遍
- 暴力 → DP：原 P5490 的失败案例（4 重循环），提醒不要"看到就写，先估复杂度"

**口诀**（让他抄到本子上）：
```
⛔ 三不写：
  1. 不写 #define int long long
  2. 不写不带 ios::sync 的 cin/cout
  3. 不写不估复杂度的循环
✅ 三必写：
  1. using ll = long long
  2. ios::sync_with_stdio(false); cin.tie(nullptr);
  3. 草稿纸先估 O(?) 再写
```
