填写说明

复赛最可惜的不是「不会做」，而是「会做却爆零」——文件名错一个字母、freopen 被注释忘恢复、答案变量忘清空，整题就是 0 分。本表把复赛防爆零拆成两部分共 15 个自查点（机试环境操作 10 项 + 代码防爆零 5 项），请逐项如实作答，提交后立即看到你的爆零风险等级和整改建议。

注意：不是每题选「是」才安全——第二部分中部分题目「否」才是正确答案。请逐题看清再选，选中后选项颜色会即时提示该项是否安全（蓝 ✓ = 安全，红 ✕ = 有风险），请凭实情作答，不要为凑分反选。

第一部分 · 机试环境操作（10 项）
1*必填
拿到题目之后，你是否知道在桌面或者 D 盘新建一个文件夹(具体以监考老师要求为准)，文件夹的名称为你本人的准考证号(如题示例)
2*必填
建立好文件夹以后，你是否知道在此文件夹下面再次建立4个文件夹，文件夹的名称为题目的目录名称(如题示例)
注意：文件夹的名称一定要和目录名称一致，一个字母都不可错哦!否则直接零分。建议直接复制题目目录名称，避免打错。
3*必填
建立这4个文件夹以后，以第一道题为例: 打开第一个文件夹(candy)，你是否知道先查看文件的扩展名是不是打开了(如题示例)
4*必填
如果文件的扩展名已经是打开的状态，你是否明白要新建一个.cpp文件，以第一道题为例(如题示例)
5*必填
你是否知道以同样的方式，再建立一个.in文件(如题示例)
6*必填
你是否明白双击打开 .cpp 文件，就要开始写程序框架+文件读写了
int main(){
    freopen("candy.in","r",stdin);
    freopen("candy.out","w",stdout);
    return 0;
}
7*必填
此时，你是否知道需要测试一下上述操作
int main(){
    freopen("candy.in","r",stdin);
    freopen("candy.out","w",stdout);
    int n;
    cin >> n;
    cout << n;
    return 0;
}
8*必填
如果你发现程序运行完成以后直接结束，没有让你输入。你是否知道打开 candy 这个文件夹后发现多了一个 candy.out 的文件，也明白当出现这个文件以后，证明自己操作正确
9*必填
你是否掌握如何验证程序的正确性呢? 你需要打开 candy.in 文件，试着输入一个5，然后保存，关掉文件，然后打开 candy.cpp 该程序，然后点击运行，会发现输出的结果5 出现在了 candy.out 文件里面了，这就说明你的操作是正确的。
本地自测闭环：candy.in 里写 5 → 编译运行 → candy.out 里出现 5，这条「读文件 → 写文件」的链路才算真正通了。
10*必填
最后提交题目的时候，你是否清楚需要再次检查 freopen 语句有没有被注释掉，如果调试过程中注释掉了 freopen，一定要去掉注释 // (如图所示)
int main(){
    // freopen("candy.in","r",stdin);
    // freopen("candy.out","w",stdout);
    return 0;
}
交卷前最后一遍：全局搜索 freopen，确认两句都没有被 // 注释掉——调试时注释了忘了恢复，是每年最高发的冤案。
第二部分 · 代码防爆零（5 项）
11*必填
题目有多组测试数据 while(T--) 时，你是否知道每一组都要把数组、vis、cnt、答案变量等重新清空，而不是只清一部分？
// 每一组数据开头，先把上组的痕迹全部擦掉
while(T--){
    cnt = 0;                          // 计数器归零
    memset(vis, 0, sizeof(vis));    // 访问标记清零
    // ...读入本组数据，正常求解
}
高频爆零：上一组数据污染下一组——单组测对、交上去全错。清空要当成和读入一样固定的开头动作。
12*必填
写累加、相乘的答案时，你是否曾忘记看数据范围、没开 long long（或没写 1LL），导致答案溢出算错？
long long ans = 0;              // 答案变量用 long long
ans += 1LL * a[i] * b[i];      // 先提升再相乘，防 int 溢出
隐形杀手：int 最大约 21 亿，数据范围一大就爆。答案全乱但编译不报错、小样例也看不出来——交卷前逐题检查答案类型。
13*必填
样例过了以后，你是否会不自己造边界数据再测（n=1、n=最大、全 0、全部相同、答案最大），就直接交卷？
样例过 ≠ 对：复赛里「样例全过最后爆零」一半栽在边界上。手搓边界数据，再和暴力程序对拍，才是交卷前的标准动作。
14*必填
改完代码，你是否经常忘了按 Ctrl+S 保存，就直接编译运行、交上去的是旧版？
年度冤案：编辑器里明明改好了，磁盘上还是旧版本，交上去的是半小时前的代码。先保存、再编译，交卷前每份 .cpp 都按一次 Ctrl+S。
15*必填
交卷前，你的题目文件夹里是否还留着 .in / .out / .exe 或旧版本没有清掉？
合规红线：可执行文件、测试数据、旧版本都属于「有效答案以外的文件」，NOI 系列赛明确不允许，可能整题甚至整场判零。交卷前每个文件夹逐一清场。
